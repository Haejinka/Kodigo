## Database changes

M12 lease authority snapshot keyed cashier/terminal/shift, issue/expiry/MFA/activation/contract/catalog/sequence bounds, an append-only lifecycle event table, and a terminal cursor with confirmed and currently reserved sequence. Current profile membership/role is rechecked on ingest.

## Backend work

`issue_offline_lease` creates an online-only `pending_stock` identity/time/sequence envelope for a cashier's own active shift. It cannot authorize an offline sale. The server reserves 100 sequence values beginning at `last_confirmed_sequence + 1`; a pending-stock lease revoked or expired before activation cannot have authorized checkout, so that range may be reused. T52 attaches exact lots and server-computed quote snapshots and atomically activates it. An activated lease blocks reissue until reconciliation, even after revocation; revocation never releases stock grants. `revoke_offline_lease` and `get_offline_lease` require current store authorization. Defaults are 8 hours and at most 100 terminal operations. No offline login, privilege elevation, approvals or digital service completion.

## Frontend work

Lease request requires an unlocked local key session, matching cashier/store/terminal scope, and an empty acknowledged terminal lane. Persist the complete lease snapshot encrypted at rest; keep only lease/store/terminal/cashier IDs clear for IndexedDB lookup. `pending_stock` cannot pass the local offline-sale guard. UI display/renewal is deferred until T24 shift controls are operational; logout cannot reassign roles or remove pending work.
